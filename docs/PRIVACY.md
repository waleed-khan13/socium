# Socium privacy notice

Socium is a localhost application. Workspace settings, drafts, connector configuration, audit events, and lead records are stored in SQLite on the operator's computer. API keys and connector credentials are encrypted locally with the installation's master key. The Socium project does not receive this local data because it does not operate a hosted backend.

On Windows, the native Rust helper performs the tray, folder-picker, shortcut, and login-start operations. It reads only the local runtime-state file required to open or stop the active localhost instance; it does not upload files, credentials, or usage data and does not place the local control token in command-line arguments.

The confirmed brand profile may contain a website, location, products or services, target audience, business goals, call to action, language, voice, content pillars, restricted claims, branded hashtags, colors, visual direction, and references to locally stored media. Socium sends the confirmed textual profile fields and the operator's current content brief to the selected AI provider only when the operator requests generation. The provider returns draft copy, hashtags, a call to action, an image prompt, visual exclusions, alt text, and rationale; Socium validates and stores that content kit locally for human review. Unconfirmed expanded fields are not added to the prompt. Logo and reference-image bytes remain in the local Media Library and are not attached to text-generation requests. With local AI, the generation context remains on the computer; with a cloud AI provider, that provider receives it under its own privacy terms.

First-run progress consists of local timestamps, the current wizard step, and non-secret fingerprints of the confirmed storage paths and verified AI settings. It remains in SQLite and is not telemetry. Testing a provider sends the minimal provider-specific model-list request described in the setup screen; Socium stores only whether the exact saved settings passed, never a response containing the API key.

Telegram and Slack approval messages use opaque local action IDs. SQLite stores the associated post ID, exact revision, transport, issue and expiry times, remote message reference, selected action, and terminal state for replay protection and auditability. These records expire after 72 hours and contain no connector credential or post copy. Telegram and Slack receive the reviewed post copy and generated image because the operator explicitly selected that approval transport; Edit handoffs and action state remain on the local computer.

Scheduler lease tokens, lease expiry, missed-work timestamps, and recovery reasons are operational metadata stored only in local SQLite. They are not telemetry and are never sent to Socium. When there is no unexpired remote approval action, Telegram polling and the Slack approval relay remain inactive. The broker retains only encrypted short-lived OAuth handoffs, hashed relay credentials, and minimal signed Slack action envelopes; provider tokens are transferred to the encrypted local vault. Overdue publication is not sent automatically after restart; the operator must choose Run now, Reschedule, or Skip in the local dashboard.

Lead records may include a deterministic ICP score, its structured business-fit reasons, the profile version used, and a separately stored human correction with its required explanation. Scoring runs inside the local FastAPI process and does not send lead data to an AI provider. Operators should not configure criteria based on protected or sensitive personal traits.

Lead records can also contain an operator-selected legal basis, consent state, supporting purpose/evidence note, retention review date, and locally stored outreach drafts. When the operator explicitly generates outreach, the configured AI provider receives the sender business context and limited lead business fields needed for that draft. Socium does not send the resulting email. Only an operator-approved current revision can be exported as CSV.

The Local SEO lab requests an operator-supplied public URL and stores a local snapshot containing the requested/final URL, hostname, HTTP status, derived page metrics, deterministic checks, category scores, crawler identity, timing, and timestamp. The fetched HTML is analyzed in memory and discarded. Version 0.9 does not send SEO snapshot data to the configured AI provider and does not claim to contain Search Console, Lighthouse, or PageSpeed data.

Connected providers receive only the data needed for an operator-requested action. For Google Places discovery, the search query, region/language options, network address, and normal request metadata are sent directly from the local FastAPI process to Google Maps Platform. Google's handling of that request is governed by the [Google Privacy Policy](https://policies.google.com/privacy). Places result content is returned with `Cache-Control: no-store`, kept only in the active browser state, and not written to SQLite. The API key stays in the encrypted connector vault.

If the operator chooses **Crawl public site**, Socium requests the selected public website with an identified user agent, respects `robots.txt`, and extracts limited business/contact fields from up to four allowed same-site pages. Those independently sourced fields enter the lead vault only after the operator selects **Add to vault**. Durable suppression records prevent later imports from silently reactivating an opted-out identity.

Operators are responsible for securing local data and backup archives, choosing and reviewing retention periods, responding to data-subject requests, and deleting or suppressing records when required. The System screen can create a consistent local archive containing SQLite, the matching encryption key, and durable assets; it never uploads that archive. The application can export a lead and its outreach drafts as JSON. Permanent deletion removes that lead, its deduplication identities, and its outreach drafts from the active SQLite database after a written reason and typed confirmation; the reason text is not retained, and the audit trail keeps only the action, record ID, and timestamp. Retention expiry is a review signal and does not silently delete data. Removing a connector deletes its locally encrypted credentials; uninstalling the software does not automatically delete backups made by the operator.

The automatic update check runs no more than once every 24 hours while the local application is running. Its HTTPS request identifies only the Socium version, operating system, and CPU architecture needed to choose an artifact; business content, credentials, database paths, and usage analytics are not sent.
